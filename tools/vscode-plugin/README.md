# CodeOne cmap preview

View the pseudo-C view (cmap) of `.bx` files side by side in VSCode.

Open a `.bx` file and click the preview button in the top-right corner of the editor title bar; the `.cmap` generated by `c1 --cmap` then appears in a split view on the right. When you save the `.bx`, the preview refreshes automatically—the same feel as the Markdown preview.

For the mapping rules, see [`cmap.md`](../../cmap.md) at the project root.

## Installation

**Development debugging** (no packaging required):

```bash
code tools/vscode-plugin
```

Press <kbd>F5</kbd> in the opened window to start an "Extension Development Host" window with the plugin already active.

**Package and install**:

```bash
cd tools/vscode-plugin
npx @vscode/vsce package        # produces codeone-cmap-0.0.1.vsix
code --install-extension codeone-cmap-0.0.1.vsix
```

This plugin has **no npm dependencies**, so `npm install` is not needed.

## Usage

1. Open any `.bx` file
2. Click the preview button in the title bar (or search for `CodeOne: Preview cmap` in the command palette)
3. The corresponding `.cmap` appears on the right, with C syntax highlighting
4. Edit and save the `.bx` → the preview panel updates automatically

## Settings

| Setting | Default | Description |
|---|---|---|
| `codeone.c1Path` | `""` | Path to the `c1` executable. Leave empty for automatic detection |

Automatic detection order:

1. `<workspace>/ssa/c1/c1` (built inside the repository)
2. `<workspace>/toolchain/*/bin/c1` (installed by `./install.sh`)
3. `c1` on `PATH`

## Implementation notes

`c1 --cmap` writes the `.cmap` **next to the input file**. To avoid leaving generated files in the source tree, the plugin first copies the `.bx` to `$TMPDIR/codeone-cmap/<path hash>/`, runs c1 there, and then opens the artifact. As a result, no `.cmap` files appear in the workspace.

The preview opens in a plain text editor (not a webview), so search, navigation, and selection/copy all work.

Highlighting comes from the plugin's bundled TextMate grammar (`syntaxes/cmap.tmLanguage.json`): C-style code coloring, plus cmap-specific `>>>`, `φ(...)`, and `zext<T>(...)` notation and atomic operation names.

`.cmap` has its **own language id** (`cmap`) and is not attached to C—so no C/C++ semantic checks run, and SSA width types such as `int32` are not underlined with squiggles. This is intentional: cmap was never designed to be compilable.

## Known limitations

- One `.bx` maps to one preview panel; previewing another file replaces the current preview tab (consistent with Markdown preview behavior)
- Synchronized scrolling is not supported yet
- The preview content is read-only—it is a generated artifact, and any edits are overwritten on the next refresh
